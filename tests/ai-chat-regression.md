# AI Chat 防偏回归场景

用于维护者验证筛选行为；不是 Skill 的来源清单，不随运行时指令加载。每次执行须实际查看图像或页面，不能只检查规则关键词、标题或候选自报的标签。原站可能更新，以下链接只是可复查的场景线索，不保证持续可用。

## 基准请求

> 用 UIPicks 帮我找几个网页 AI 对话 Agent 的聊天窗口样式。我要聊天进行中的画面，有用户提问、AI 回答和继续输入区；优先多轮对话。免费匿名查看参考，不要求获得源码。

把候选打乱后逐图检查，记录符合、不符、未知与可见证据，再决定推荐。合格只是进入设计评审的前提，不等于必须推荐。

## 条件变化测试

1. **明确要开场页**：改问“只找 AI 欢迎页和首次输入的空状态”。重新判断；符合开场要求的图可以入选，不沿用对话正文门槛。
2. **明确要多轮**：改问“必须能看到至少两轮用户提问和 AI 回复”。只展示一问一答的图或仅输入了追问但尚无回复的图，不足以通过；可以用配套上下文截图证明。
3. **还要求源码免费**：改问“需要免费匿名获取源码”。Arc UI 与 BoardUI 的付费源码路径须排除，即使演示免费；其他来源也逐条核对。
4. **工具失败或证据缺失**：只能查看开场图、只有文字说明、页面超时或找不到原图时，不将候选提升为主推荐，不声称交互通过；说明缺口或更换来源。
5. **数量不足**：要求三个参考，但只有两个通过门槛。交付两个并说明不足，不从开场图中补第三个。

## 通过条件与结果记录

- 基准请求的每张主参考图均实际可见用户提问、AI 正文回复，以及同图或配套截图中的继续输入区；明确要求多轮时有两轮完整问答证据。
- 所有已确认的开场图和错误对象均被拒绝；未知图像只作线索。切换需求时能改变入选条件。
- 审美与体验比较发生在门槛通过之后；文字说明、演示数据、交互检查及源码费用与实际证据一致。
- 每次记录日期、需求约束、各候选决定及原因、所看画面/来源、已执行的交互、限制和结果。截图可留在任务临时目录，不提交进本仓库或 UIPicks 图片库。
- 这些场景验证可复查的行为边界；一次通过不等于所有模型、工具和后续原站版本都不会偏离。
